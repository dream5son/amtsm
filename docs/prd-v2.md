这是在《A股交易信号监控告警系统 (V1.0)》基础上迭代的第二版产品需求文档。V1.0 解决了"发现买卖点"的问题，但没有对接用户的真实持仓状态——用户买入后能赚多少、该在什么价位止盈、什么价位止损，系统完全无法感知。V2.0 的核心目标是把系统从"选股/择时监控工具"升级为"全生命周期持仓风控工具"：新增持仓登记（持有量、买入价、减持记录），并围绕交易实务中最容易导致亏损扩大或利润回吐的两个环节——**止损**与**锁定利润**——设计一套系统化、可配置、以降低亏损概率和提升盈利留存概率为目标的信号引擎。

# 产品需求文档 (PRD)：A股交易信号监控告警系统 (V2.0)

## 1. 产品概述

### 1.1 V2.0 迭代背景

V1.0 版本已实现"N日高低点区间"策略的买卖点提醒，解决了**从 0 到 1（发现机会）**的问题。但在实际使用过程中暴露出明显缺口：

* 系统不知道用户**是否已经买入**、买了**多少仓位**、**成本价**是多少，因此无法区分"该提醒买入"还是"该提醒止盈/止损"，只能对所有关注股票统一套用同一套高低点信号，持仓和空仓的股票被一视同仁地对待。
* V1.0 的卖点逻辑（$P \ge High_{max} \times Y$）本质上是"技术性高位"信号，与用户的真实盈亏毫无关系。用户可能在高点买入被套，此时该信号完全失效；也可能用户已经获利颇丰，但系统在利润快速回吐、由盈转亏之前没有任何预警。
* 交易实践反复证明，散户亏损的最主要原因不是"选不到好的买点"，而是**不止损（亏损扩大）**和**不止盈（利润回吐甚至由盈转亏）**。V1.0 完全没有覆盖这两个环节。

因此 V2.0 在 V1.0 全部能力基础上，新增：

1. **持仓管理**：记录每只自选股的持有数量、买入价格（支持多次加仓的加权成本）、减持（部分/全部卖出）记录。
2. **止盈止损策略引擎**：结合持仓成本与价格走势，提供"初始止损→保本止损→阶梯移动止盈"的组合风控逻辑，目标是在交易层面**尽量提升锁定盈利的概率、尽量降低亏损扩大的概率**。
3. **回测系统【优先级提升，由 V3.0 展望提前至 V2.0】**：提供历史数据回测能力，验证不同 (N, X, Y, StopLossPct, TrailingLadder) 参数组合在过去数年的历史胜率、平均盈亏比和最大回撤。V1.0 原规划将回测系统列为 V3.0 远期展望，但实践中用户在配置 3.2 节的策略参数、以及判断某只自选股是否值得建仓时，一直缺少数据依据、只能凭经验拍脑袋设定 N/X/Y 和止盈止损参数。回测系统本质上是**选股与参数调优的决策支持工具**，与本期新增的持仓管理、止盈止损引擎强相关（回测同样需要模拟止盈止损的三级止损体系），因此本版本将其优先级提升，与止盈止损引擎一并纳入 V2.0 交付范围。

### 1.2 目标用户

与 V1.0 一致：具有一定交易经验、希望通过量化规则监控价格区间和持仓盈亏，但无法时刻盯盘的A股个人投资者。V2.0 进一步覆盖**已经持仓、需要纪律化止盈止损**的用户场景。

### 1.3 V2.0 范围声明

* 本期继续**不包含自动化交易（API下单）**，止盈止损信号仍以微信通知形式触达，由用户手动执行。
* 持仓数据（持有量、成本价）由**用户手动登记/维护**，不对接券商持仓接口（券商持仓自动同步列入后续演进路线）。
* 止盈止损参数（比例、阶梯）默认提供基于交易经验的推荐值，同时支持用户自定义覆盖，以适配不同风险偏好和不同股票的波动特性。
* 回测系统基于历史行情数据做**离线模拟**，不代表实盘一定能获得同等收益（无法完全还原实际滑点、流动性冲击、涨跌停无法成交等因素），回测结果仅作为参数调优和选股决策的**参考依据**，不构成投资建议，需在界面上做相应提示。

## 2. 核心功能模块划分（V2.0 全景）

在 V1.0 四大模块基础上，新增第 5、6、7 三个模块。其中**回测系统（模块 7）原规划于 V3.0 展望，本版本因其可为选股与参数调优提供数据支撑而提升优先级，提前至 V2.0 交付**：

1. **股票池管理 (Watchlist)**：搜索、添加、删除关注的A股代码。*[V1.0 已有，V2.0 扩展持仓字段展示]*
2. **策略参数配置 (Configuration)**：计算周期（N）、买入阈值（X）、卖出阈值（Y）。*[V1.0 已有]*
3. **数据计算引擎 (Data Engine)**：获取历史日线数据及盘中实时行情，执行策略逻辑计算。*[V1.0 已有，V2.0 扩展持仓盈亏计算]*
4. **消息通知中心 (Notification)**：触发买卖点/止盈止损后的微信通知下发与频控管理。*[V1.0 已有，V2.0 扩展通知模板]*
5. **持仓管理 (Position Management)【V2.0 新增】**：登记买入（建仓/加仓）、登记减持（部分/全部卖出），维护加权平均成本、持仓数量、持仓期间最高价等状态。
6. **止盈止损策略引擎 (Risk Control Engine)【V2.0 新增】**：基于持仓成本与实时价格，执行初始止损、保本止损、阶梯移动止盈（追踪止损）等组合规则，生成止盈/止损提醒。
7. **回测系统 (Backtesting Engine)【V2.0 新增，优先级提升】**：提供历史数据回测功能，验证不同 (N, X, Y, StopLossPct, TrailingLadder) 参数组合在过去数年的历史胜率、平均盈亏比和最大回撤，为选股决策与参数调优提供数据依据。

## 3. 详细功能需求

### 3.1 股票池管理（在 V1.0 基础上扩展）

沿用 V1.0 全部能力（搜索添加、模糊搜索、移除关注、停牌退市状态同步），列表展示字段在原有基础上新增：

* **持仓状态**：`空仓监控` / `持仓中` / `部分减持`。
* **持有数量**：股（若为空仓，则显示为 0 或"-"）。
* **持仓成本价**：加权平均买入价（若为空仓，则不展示）。
* **浮动盈亏**：$(当前价 - 持仓成本价) \times 持有数量$，及浮动盈亏比例 $\dfrac{当前价 - 持仓成本价}{持仓成本价}$。
* **当前止损/止盈参考价**：来自第 3.5 节止盈止损引擎实时计算的动态止损线。

> 产品设计原则：**"空仓监控"与"持仓中"两种状态复用同一个自选股列表，而非拆分成两个独立列表**。这样用户可以在一个界面里同时看到"哪些股票值得买入"和"哪些持仓需要止盈止损"，符合个人投资者的真实决策习惯。

### 3.2 策略参数配置模块（沿用 V1.0，新增止盈止损参数入口）

沿用 V1.0 的 N（计算周期）、X（买入系数）、Y（卖出系数）配置，新增以下**止盈止损参数**（详细定义见 3.5 节），同样遵循"全局默认 + 单股覆盖"的配置模式：

| 参数 | 含义 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `StopLossPct` | 初始止损比例 | `8%` | 相对**买入成本价**的最大可容忍亏损 |
| `BreakEvenTriggerPct` | 保本止损触发盈利比例 | `10%` | 浮盈达到该比例后，止损线自动上移至成本价（含手续费缓冲） |
| `BreakEvenBufferPct` | 保本缓冲比例 | `0.5%` | 止损线上移至"成本价 × (1 + 该比例)"，覆盖交易手续费和印花税，避免"保本止损"实际保不了本 |
| `TrailingLadder` | 阶梯移动止盈规则 | 见下表 | 浮盈越高，回撤容忍度越收紧，见 3.5.3 |
| `EnablePartialTakeProfit` | 是否启用分批止盈 | 关闭（可选开启） | 开启后按阶梯目标位提示分批减持，而非一次性清仓 |

**默认阶梯移动止盈规则（`TrailingLadder`）**：

| 浮盈区间（相对成本价） | 允许从持仓期间最高价回撤的比例 | 设计意图 |
| --- | --- | --- |
| `< 10%`（尚未触发保本止损前） | 不适用，采用初始止损 `StopLossPct` | 利润太薄，优先保护本金，不做移动止盈 |
| `10% ~ 20%` | `15%` | 保本之后给予正常波动空间，避免被洗出局 |
| `20% ~ 50%` | `10%` | 利润增厚后适度收紧，锁定更多既得利润 |
| `≥ 50%` | `6%` | 大幅盈利后严格锁盈，防止趋势反转导致利润大幅回吐 |

> 该表为系统推荐默认值，支持用户按个股波动特性（如高波动成长股 vs 低波动蓝筹股）自定义覆盖每一档的回撤容忍比例。

### 3.3 持仓管理模块【V2.0 新增】

#### 3.3.1 登记买入（建仓 / 加仓）

* 用户可对自选股池中的任意股票登记一笔买入记录，字段包括：**买入数量**、**买入价格**、**买入日期**（默认当日，可回溯补录历史买入）。
* 若该股票此前已有持仓（加仓场景），系统按**加权平均成本法**重新计算持仓成本：

$$AvgCost_{new} = \frac{AvgCost_{old} \times Qty_{old} + Price_{buy} \times Qty_{buy}}{Qty_{old} + Qty_{buy}}$$

* 加仓后持仓数量累加；同时**不重置**"持仓期间最高价"字段的历史值，仍取加仓前后价格序列中的最大值，避免移动止盈的锁定进度因加仓而"归零"。
* 登记买入后，该股票状态从 `空仓监控` 切换为 `持仓中`，止盈止损引擎开始对其生效；原有 V1.0 的"买入信号"提醒对已持仓股票**默认停止推送**（避免对已持仓股票反复提示"买入"），除非用户主动开启"持仓中仍监控加仓机会"选项。

#### 3.3.2 登记减持（部分 / 全部卖出）

* 用户可对持仓中的股票登记一笔减持记录，字段包括：**卖出数量**（不可超过当前持有数量）、**卖出价格**、**卖出日期**。
* **部分减持**：持有数量扣减对应卖出数量，**加权平均成本价保持不变**（减持不改变剩余仓位的历史买入成本），状态变更为 `部分减持`。
* **全部减持（清仓）**：持有数量归零，状态回退为 `空仓监控`，成本价、持仓期间最高价、动态止损线等持仓相关字段清空；该股票重新进入 V1.0 的"N日高低点买入信号"监控逻辑，等待下一次建仓机会。
* 减持记录用于统计已实现盈亏（本期展示层面的加分项，非核心链路强制要求），公式：$已实现盈亏 = (卖出价 - 持仓成本价) \times 卖出数量$。

#### 3.3.3 持仓列表与明细展示

* 持仓中的股票在自选股列表中高亮展示核心风控信息：持仓成本价、当前价、浮动盈亏（金额+比例）、当前止损参考价、距止损线的百分比空间。
* 支持查看单只股票的买入/减持流水明细（时间、数量、价格），便于用户复盘。

### 3.4 行情监控与核心计算逻辑（区分"空仓"与"持仓"两种模式）

系统对同一只自选股，依据其持仓状态，**互斥地**执行两套逻辑中的一套：

* **空仓监控模式**（持仓状态为 `空仓监控`）：完全沿用 V1.0 的 N 日高低点买卖点逻辑（3.4.1 节，即原 V1.0 3.3 节），寻找建仓机会。
* **持仓风控模式**（持仓状态为 `持仓中` 或 `部分减持`）：执行 3.5 节的止盈止损策略引擎，寻找减仓/清仓时机；同时仍可选保留 V1.0 的 $P \ge High_{max} \times Y$ 卖点信号作为"技术高位"的辅助参考通知（不作为强制止盈依据，避免与止盈止损引擎的核心结论冲突）。

#### 3.4.1 空仓监控模式（沿用 V1.0，逻辑不变）

* $N日最低点(Low_{min})$ / $N日最高点(High_{max})$：过去 N 个交易日（不含当日）前复权高低点。
* **买点信号**：$P \le Low_{min} \times X$，触发"发现买入信号"通知。

### 3.5 止盈止损策略引擎【V2.0 核心新增】

#### 3.5.1 设计原则（为什么这样设计）

止盈止损规则的设计目标是**从交易统计规律出发，最大化"整体盈亏期望"，而非单次判断的绝对正确率**。具体遵循以下三条被交易实践反复验证的原则：

1. **止损要快、止盈要慢（截断亏损，让利润奔跑）**：亏损时应尽快按纪律离场，避免小亏拖成大亏；盈利时不应过早锁死，应给予价格正常波动的空间，让趋势充分兑现，否则容易"赚了指数不赚钱"。
2. **止损线只能向有利方向移动，不能后退（棘轮机制 / Ratchet）**：无论是保本止损还是移动止盈，止损参考价一旦上移就不再下移，避免用户在盈利后主观放宽止损、把已经到手的利润重新置于风险之中。
3. **止损幅度应与个股波动特性匹配**：波动越大的股票，过窄的止损越容易被正常波动"误杀"（假止损），因此止损/回撤容忍比例支持按个股覆盖，而非全局一刀切。

#### 3.5.2 三级止损体系

止盈止损引擎按下述**优先级从低到高**依次判断，止损参考价 $StopPrice$ 只会越来越高（越来越靠近甚至超过当前价的方向收紧），不会倒退：

**① 初始止损（建仓保护）**

* 建仓后立即生效，止损参考价：

$$StopPrice = AvgCost \times (1 - StopLossPct)$$

* *业务解释*：买入后若价格反向下跌超过设定比例（默认8%），说明当初的买入判断大概率有误或大盘/个股出现超预期利空，应立即止损离场，防止小亏演变为大亏——这是控制"最大回撤"、保护本金安全的第一道防线。

**② 保本止损（成本保护，消除本金风险）**

* 当浮动盈利比例达到 `BreakEvenTriggerPct`（默认10%）时自动触发，止损参考价上移为：

$$StopPrice = \max\left(StopPrice_{当前}, \; AvgCost \times (1 + BreakEvenBufferPct)\right)$$

* *业务解释*：一旦浮盈达到一定安全垫，就把止损线提高到成本价附近（略高于成本价以覆盖手续费），确保**从这一刻起这笔交易在最坏情况下也不会亏钱**，消除本金风险后可以更从容地持有以博取更大收益。

**③ 阶梯移动止盈（追踪止损，锁定利润）**

* 系统持续记录**持仓期间最高价** $HighestSinceHold$（每次盘中价格创出持仓新高时更新，只增不减）。
* 依据当前浮盈比例，在 `TrailingLadder`（见 3.2 节）中匹配对应档位的回撤容忍比例 $DrawdownPct$，动态计算：

$$StopPrice = \max\left(StopPrice_{当前}, \; HighestSinceHold \times (1 - DrawdownPct)\right)$$

* *业务解释*：价格每创新高，止损线就跟随上移，浮盈越丰厚、回撤容忍度越收紧（见3.2节阶梯表），实现"利润越多、保护越严"，在保留继续上涨空间的同时，把已经实现的账面利润逐步转化为"锁定利润"，防止冲高回落后利润大幅回吐甚至由盈转亏。

#### 3.5.3 触发判定与通知

* **实时判断**：每次盘中轮询获取最新价 $P$ 后，与该持仓股票当前的 $StopPrice$ 比较：
* 若 $P \le StopPrice$，触发**止盈/止损提醒**。系统根据触发时的浮盈状态自动区分文案与类型：
* 若触发时浮亏（$P < AvgCost$）：判定为 **止损信号**。
* 若触发时浮盈但低于最高点（保本止损或移动止盈生效区间）：判定为 **止盈信号（锁定利润）**。
* **分批止盈（可选）**：若开启 `EnablePartialTakeProfit`，则在浮盈进入 `TrailingLadder` 更高一档时（而非等到真正触发回撤止损），额外提示"建议减持X%仓位锁定部分利润，剩余仓位继续持有"，兼顾"落袋为安"与"不踏空后续涨幅"。
* **信号频控**：沿用 V1.0 的单日单信号频控原则（同一股票同一交易日同一信号类型最多推送1次），避免价格在止损线附近反复穿越导致通知轰炸；止损/止盈信号额外增加规则：**触发一次止损/清仓类信号后，当日不再重复计算该股票的止盈止损（因为理论上用户应已离场或已收到明确指引）**，次日按最新持仓状态重新计算。

#### 3.5.4 止盈止损与买入信号的联动规则

* 已持仓（`持仓中`/`部分减持`）的股票**默认不再推送 V1.0 的买入信号**，避免用户对同一只股票同时收到"买入"和"止损"两类矛盾信息；如需支持"逢低加仓"策略，可在策略配置中单独开启"持仓中允许加仓提醒"开关，加仓提醒与止盈止损提醒在通知文案中明确区分。
* 空仓股票（`空仓监控`）不计算止盈止损（无持仓、无成本价，逻辑上不适用）。
* 全部减持清仓后，止盈止损状态清空，重新回到空仓监控模式，等待下一次买入信号。

### 3.6 告警通知系统（沿用 V1.0，扩展持仓相关模板）

在 V1.0 买点/卖点模板基础上，新增：

* **止损模板**：【交易助手】止损提醒！您持有的[股票名称]当前价格[当前价]，已跌破止损线[止损参考价]（成本价[成本价]，浮亏[浮亏比例]），建议及时止损离场，控制风险。
* **保本止损/移动止盈模板**：【交易助手】止盈提醒！您持有的[股票名称]当前价格[当前价]，已触及移动止盈线[止损参考价]（持仓期间最高价[最高价]，当前浮盈[浮盈比例]），建议及时锁定利润，可考虑减仓或清仓。
* **分批止盈提醒模板**（开启该功能时）：【交易助手】阶梯止盈提醒！您持有的[股票名称]浮盈已达[X]%，建议减持[建议比例]仓位锁定部分利润，剩余仓位继续持有博取更大收益。
* **发送实现**：沿用 `wechatpy` SDK，止盈止损类通知与 V1.0 买卖点通知共用同一套微信通道与频控机制。

### 3.7 回测系统模块【V2.0 新增，优先级提升】

#### 3.7.1 为什么要提升优先级

V1.0 原本把回测系统列为"V3.0 展望"中的远期能力，仅描述为"验证策略在过去1年的历史胜率和收益率"。但在 V2.0 实际落地持仓管理和止盈止损引擎的过程中，暴露出一个更迫切的问题：**用户在 3.2 节配置 N、X、Y、`StopLossPct`、`TrailingLadder` 等参数时，完全依赖默认值或个人经验，无法预知某组参数在某只股票的历史行情上表现如何**，也无法判断"这只自选股当前是否适合按现有参数建仓"。回测系统本质上是一个**数据驱动的选股与调参决策支持工具**，能直接提升 V1.0/V2.0 全部信号引擎的可用性，因此本版本将其优先级从"远期展望"提升为**与止盈止损引擎同批交付的 V2.0 核心模块**。

#### 3.7.2 功能目标

* 让用户在**投入真实资金之前**，用历史数据验证一组 (N, X, Y, StopLossPct, TrailingLadder) 参数组合的历史表现，替代"拍脑袋"式的参数设定。
* 为股票池中的每只自选股提供"该参数组合在这只股票历史上是否有效"的量化参考，辅助用户判断**是否值得将其纳入重点关注、是否适合当前配置的参数建仓**，即为选股提供数据支撑。
* 支持横向对比多组参数组合的回测结果，辅助用户挑选历史表现更优的参数，反哺 3.2 节的策略参数配置。

#### 3.7.3 回测输入

* **标的范围**：支持对单只股票、股票池中多只股票、或全部自选股批量发起回测。
* **参数组合**：(N, X, Y, StopLossPct, TrailingLadder) 五项参数，可使用当前全局/单股配置作为默认值，也支持自定义一组或多组参数组合（用于对比调优，即"参数网格"）。
* **回测区间**：默认过去 **3 年**，支持切换为过去 1 年 / 3 年 / 5 年（或用户自定义起止日期），并复用 V1.0 已接入的日线历史数据接口，**统一使用前复权数据**（与 3.4.1 节实时监控逻辑保持同一基准，避免除权除息导致的历史高低点失真）。

#### 3.7.4 回测逻辑（模拟引擎）

* 按交易日逐日回放历史行情，在每个模拟交易日：
  1. 若当前处于"空仓"模拟状态，按 3.4.1 节买点逻辑（$P \le Low_{min} \times X$）判断是否"模拟买入"（建仓）；
  2. 若当前处于"持仓"模拟状态，按 3.5 节三级止损体系（初始止损 → 保本止损 → 阶梯移动止盈）逐日滚动计算 $StopPrice$，判断是否触发"模拟卖出"（止损/止盈离场）。
* 每完成一次"模拟买入 → 模拟卖出"的完整交易，记录一笔虚拟交易流水（买入日期/价格、卖出日期/价格、持仓天数、盈亏金额与比例），直至回测区间结束。
* 回测引擎与 3.4、3.5 节的实盘信号计算逻辑**复用同一套判定代码**，确保"回测时验证的规则"与"实盘运行的规则"完全一致，避免"回测很赚钱、实盘不生效"的逻辑不一致问题。

#### 3.7.5 回测输出指标

| 指标 | 说明 |
| --- | --- |
| 历史胜率 | 盈利交易笔数 / 总交易笔数 |
| 平均盈亏比 | 平均单笔盈利金额（或比例） / 平均单笔亏损金额（或比例） |
| 最大回撤 (Max Drawdown) | 回测区间内模拟账户净值从峰值回落的最大幅度，衡量该参数组合可能面临的最差情形 |
| 总交易次数 | 回测区间内完整"买入→卖出"周期的次数，交易次数过少时提示"样本不足，结果仅供参考" |
| 累计/年化收益率（加分项） | 回测区间内的总收益率及换算后的年化收益率，供用户直观感受策略盈利能力 |

* 支持将多组参数组合的回测结果并排列表展示，按胜率/盈亏比/最大回撤等指标排序，辅助用户快速定位历史表现较优的参数区间。

#### 3.7.6 与选股、策略配置模块的联动

* 回测结果页支持"一键应用"：用户看中某组回测表现较优的参数后，可直接将其应用为该股票的单股策略配置（3.2 节），无需手动誊抄。
* 自选股列表（3.1 节）可选展示"当前参数近 N 年回测胜率"作为选股参考角标，帮助用户在同一界面同时看到"实时信号"与"历史验证效果"。
* 回测仅作为**离线参考**，不影响实时监控引擎的运行，也不产生任何实盘通知或委托。

#### 3.7.7 非目标（本期不做）

* 不模拟资金曲线的仓位管理（如分批建仓比例、多股票资金分配），单只股票回测按"信号触发即满仓/清仓"简化处理。
* 不接入实盘资金/委托模拟，回测结果不保证实盘可复现（滑点、涨跌停无法成交等因素不纳入模拟）。

## 4. 数据与接口依赖（在 V1.0 基础上新增）

沿用 V1.0 的日线历史接口、实时行情接口、微信通知通道，新增以下数据存储与计算需求：

1. **持仓数据存储**：需新增持仓表（记录持有数量、加权平均成本、持仓期间最高价、当前动态止损参考价）及买入/减持流水表，用于加权成本计算与历史复盘。
2. **动态止损价计算**：无需额外第三方接口，基于已有的实时行情数据在内存中滚动计算 `StopPrice`，每次价格创新高时更新，逻辑与 V1.0 的高低点基准计算共享同一套实时行情轮询链路，不增加额外的行情请求次数。
3. **除权除息对持仓成本的影响**：若持仓股票发生分红送股，需按除权因子同步调整"持仓成本价"和"持仓期间最高价"，否则复权后的实时价格与未复权调整的历史成本价不可比，将导致止损线计算错误（详见第 5 节异常处理）。
4. **多年历史日线数据（回测系统新增依赖）**：V1.0 的日线接口仅需拉取近 N 个交易日用于计算高低点基准，回测系统需要拉取**过去数年（默认3年，最长支持5年）的完整前复权日线数据**，对第三方数据源（Tushare/BaoStock 等）的历史数据覆盖范围、单次拉取条数限制和调用频率有更高要求，需评估是否需要**本地落库缓存历史行情**（新增历史日线表），避免每次回测都重复请求第三方接口。
5. **回测结果存储**：需新增回测任务表与回测交易流水表，记录每次回测的参数组合、回测区间、汇总指标（胜率、盈亏比、最大回撤等）及逐笔虚拟交易明细，供用户查看历史回测记录和多组参数对比，无需每次重新计算。

## 5. 异常情况与边界处理（在 V1.0 基础上新增持仓相关场景）

沿用 V1.0 全部异常处理规则（除权除息基准重算、次新股数据不足N天、涨跌停板、接口超时重试），新增以下持仓管理相关场景：

1. **持仓股票除权除息**：股票分红送股会导致复权价格跳变，若不同步调整持仓成本价和"持仓期间最高价"，会导致移动止盈线错误跳变（误触发或漏触发）。
* *处理规则*：与 V1.0 历史高低点的处理方式一致，除权除息日由盘前任务按当日除权因子对持仓成本价、持仓期间最高价做等比例前复权调整，确保与当日实时价格同基准可比。
2. **T+1 交易限制**：A股当日买入的股份当日不可卖出。
* *处理规则*：止盈止损引擎仍可正常计算并推送提醒（提醒本身不代表下单），但系统在通知文案中对"当日买入仓位"标注"（注：当日买入部分暂受T+1限制，无法当日卖出）"，避免用户误以为可以立即操作。
3. **加仓摊薄成本导致止损线剧烈变动**：用户在浮亏时加仓摊薄成本，可能导致新的初始止损线大幅偏离用户预期。
* *处理规则*：每次加仓后按 3.3.1 节加权平均法重新计算成本价与初始止损线，并在加仓操作确认页面显式提示"加仓后新成本价：X，新止损参考价：Y"，避免用户在不知情的情况下变更风险敞口。
4. **减持数量超过持有数量 / 重复减持**：用户误操作导致减持数量大于当前持仓。
* *处理规则*：前端与后端双重校验，减持数量必须 $\le$ 当前持有数量，超出则拒绝提交并提示错误，不允许出现负持仓。
5. **止损与止盈信号同时命中新高更新**：极端行情下（如涨停后立即大幅回落），当日最高价与触发止损的最新价可能在同一个轮询周期内出现。
* *处理规则*：先更新 $HighestSinceHold$ 及对应 $StopPrice$，再用更新后的 $StopPrice$ 判断当前价是否触发信号，确保判断逻辑始终基于"最新的、最严格的止损线"，不遗漏理应触发的止损/止盈信号。
6. **涨跌停板导致无法止损/止盈**：触及止损/止盈线但股票处于跌停（无法卖出止损）或涨停（可继续持有博弈但也可能无法及时止盈）。
* *处理规则*：与 V1.0 一致，V2.0 仍正常发送提醒，交由用户结合实际盘口流动性自行判断，通知文案附加涨跌停风险提示。

## 6. 后续演进路线 (V3.0 展望)

> 说明：回测系统原列于本节，因其可为选股与参数调优提供数据支撑，本版本已将其**优先级提升并纳入 V2.0 正式交付范围**（详见 3.7 节），故从本节移除，后续版本在此基础上做进一步智能化演进。

* **止损止盈参数智能化**：基于个股历史波动率（ATR/年化波动率）自动推荐初始止损比例与阶梯移动止盈参数，替代当前固定百分比的人工配置方式。
* **回测能力增强**：在 V2.0 回测系统基础上，支持参数自动网格搜索/寻优（Grid Search）、walk-forward 滚动回测验证参数稳健性，以及多股票组合级别的资金曲线模拟。
