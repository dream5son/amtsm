# 用户故事 07：登记买卖的分层分配与确认

## 场景目标

用户在价值股上登记买入/减持时，系统按默认规则分配到底仓或波段仓，并支持高级指定与减底仓二次确认。

## 用户故事

作为一名维护真实持仓的投资者，
我希望登记买卖时系统自动合理分配到底仓或波段仓，并在动到底仓时明确确认，
以便日常操作简单，同时避免误卖底仓。

## UI 体现要点

- 买入/减持弹层在 `CORE_VALUE` 下展示「分配预览」：本次将记入底仓/波段各多少。
- 提供「高级：指定层」覆盖默认规则。
- 减持将触及底仓时弹出二次确认文案。
- `TACTICAL` 表单保持 V2，不展示分层控件。

## 参与角色

- 用户
- 登记买入/减持弹层
- Position API（含 allocation preview）

## 前置条件

- 故事 05/06 的参数与展示已具备（或至少后端分层字段可用）。

## 触发事件

- 用户点击登记买入或登记减持。

## 主流程

1. 用户输入数量与价格。
2. 前端请求分配预览（或本地按同一规则预览，最终以后端为准）。
3. 用户确认；若涉及减底仓则二次确认。
4. 后端写流水（带 `layer`）并更新分层快照与兼容总字段。

## 业务规则

- **默认买入**：优先补齐目标底仓（按 `core_ratio` 与计划总仓或当前持仓启发式——实现须在 API 文档写清）；超出部分记波段。
- **默认减持**：先减波段；波段不足部分需显式确认后减底仓。
- 加波段仓时更新波段成本与棘轮（与 V2 加仓规则一致，作用域仅卫星）。
- 减底仓不重置波段棘轮状态。

## 验收标准（Given-When-Then）

- Given 价值股底仓未满，When 买入一定数量，Then 预览显示优先进入底仓的数量。
- Given 波段仓有数量，When 减持不超过波段，Then 只减少波段且底仓不变。
- Given 减持超过波段，When 未二次确认，Then 不会改动底仓。
- Given 交易型股票，When 登记买卖，Then 无分层 UI，行为与 V2 一致。

## 非功能要求

- 预览与提交结果一致；并发改仓有乐观校验或最新持仓校验。

## 关联数据

- `position_ledgers.layer`、`positions` 分层字段
