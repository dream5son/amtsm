# 用户故事 08：底仓信号展示与人工复核

## 场景目标

系统对价值股发出 `CORE_BUILD` / `REVIEW_FUNDAMENTAL` / `CORE_TRIM` 提醒，列表与微信可感知，且任何清仓/减底仓须经用户确认。

## 用户故事

作为一名长期持有价值股的投资者，
我希望在底仓需要加仓、复核或减仓时收到明确提醒，而不是被系统自动卖掉，
以便我根据基本面自己做决定。

## UI 体现要点

- 列表信号列支持底仓类标识：`建议建底仓` / `请复核基本面` / `建议减底仓`。
- 「待复核」角标可点开简要说明与操作引导（去登记买入/减持）。
- 微信通知模板含「不会自动卖出底仓」说明。

## 参与角色

- 用户
- 盘中引擎 / 通知中心
- 列表信号展示

## 前置条件

- 股票 `tier=CORE_VALUE`；相关阈值已配置（故事 05）。

## 触发事件

- 盘中/收盘评估满足底仓信号条件；或用户查看列表信号。

## 主流程

1. 引擎评估产生底仓类信号并写告警日志。
2. 发送微信（受频控）。
3. 列表展示信号；用户可据此去登记买卖（故事 07）。

## 业务规则

- 三类信号均 **不自动改仓**。
- `REVIEW_FUNDAMENTAL` 第一版可用底仓回撤代理阈值触发；文案须说明代理性质。
- `CORE_BUILD` 在 `MANUAL` 模式下可不自动推送，或仅推送弱提醒（产品可选）；`PRICE_PROXY` 下按档位推送并披露代理规则。
- 频控：日+股+类型（`CORE_BUILD` 可含档位）；`REVIEW` 可按更长周期去重以免骚扰。

## 验收标准（Given-When-Then）

- Given 价值股底仓浮亏超过复核阈值，When 评估触发，Then 列表与通知出现复核提醒且持仓数量不变。
- Given 收到 `CORE_TRIM`，When 用户未操作，Then 底仓数量保持不变。
- Given 交易型股票，When 评估，Then 不产生上述底仓类信号。

## 非功能要求

- 通知与列表文案由同一 `signal_type` 驱动，避免不一致。

## 关联数据

- `alert_logs`、底仓评估规则、通知模板
