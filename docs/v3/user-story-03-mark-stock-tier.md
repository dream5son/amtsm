# 用户故事 03：标记自选股策略类型（tier）

## 场景目标

用户能为自选股打上 `CORE_VALUE` 或 `TACTICAL` 标签，作为后续双层策略路由的前提（第一版人工白名单）。

## 用户故事

作为一名区分价值长持与短线交易标的的投资者，
我希望在自选列表里手动标记某只股票是「价值底仓」还是「交易型」，
以便系统对它们套用不同的持仓与风控逻辑。

## UI 体现要点

- 自选行提供「策略类型」标签或操作入口。
- 编辑弹层：二选一（价值底仓 / 交易型）+ 可选备注（护城河、看好理由等）。
- 保存后列表标签立即更新。

## 参与角色

- 用户
- 前端标签编辑弹层
- Watchlist API

## 前置条件

- 股票已在自选池。

## 触发事件

- 用户点击标签或「标记策略类型」。

## 主流程

1. 用户打开编辑并选择 `CORE_VALUE` 或 `TACTICAL`。
2. 可选填写备注。
3. 提交后后端持久化 `tier` / `tier_note` / `tier_updated_at`。
4. 列表刷新展示。

## 业务规则

- 新加入自选默认 `TACTICAL`。
- 从 `CORE_VALUE` 降级为 `TACTICAL` 时，若仍有 `core_qty > 0`，拒绝并提示先处理底仓（故事 11）。
- 升级为 `CORE_VALUE` 不自动拆分已有持仓；存量数量保持在波段/整仓语义，由用户后续自行调整（与 design 迁移约定一致）。
- 本故事不要求接入基本面自动打标。

## 验收标准（Given-When-Then）

- Given 自选股为默认交易型，When 标记为价值底仓并保存，Then 列表显示价值底仓标签且刷新后仍在。
- Given 股票有底仓数量，When 尝试改为交易型，Then 保存失败并提示原因。
- Given 用户填写备注，When 再次打开编辑，Then 备注回显。

## 非功能要求

- 修改 tier 后引擎侧应能在下一轮评估前读到新值（缓存刷新）。

## 关联数据

- `watchlist.tier`、`tier_note`、`tier_updated_at`
