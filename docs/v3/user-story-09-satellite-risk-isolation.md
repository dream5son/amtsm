# 用户故事 09：波段仓风控与文案隔离

## 场景目标

确保 `CORE_VALUE` 下既有止损/止盈/分批/加仓信号只作用于波段仓，并在 UI/通知中明确隔离，避免用户误以为应清掉底仓。

## 用户故事

作为一名同时持有底仓与波段仓的投资者，
我希望止盈止损提醒明确写的是「波段仓」，
以便我执行时只处理增强仓位，继续拿住底仓。

## UI 体现要点

- `CORE_VALUE` 持仓行的止损/止盈/分批止盈/加仓标识带前缀或标签：「波段」。
- 通知标题/正文含「【波段仓】」及当前波段数量、底仓数量（底仓数量用于对照，非操作对象）。
- 波段清零后，若仍有底仓：状态仍为持仓，信号回到「可加波段/底仓复核」而非空仓 BUY 主语义（与 design 状态机一致）。

## 参与角色

- 用户
- 风控引擎（satellite 作用域）
- 列表与微信模板

## 前置条件

- 价值股同时有底仓与波段仓；波段风控参数有效。

## 触发事件

- 价格触发波段三级止损/止盈或加仓条件。

## 主流程

1. 引擎仅用 `satellite_*` 状态调用既有 risk/entry 规则核。
2. 生成 V2 类型信号，模板按价值股分支渲染。
3. 用户按提醒自行减持波段（故事 07）。

## 业务规则

- 硬约束：波段信号不得修改 `core_qty`。
- `TACTICAL` 文案保持 V2，不出现「波段」前缀。
- 规则核代码路径与 V2 共用，禁止复制公式。

## 验收标准（Given-When-Then）

- Given 价值股底仓 500、波段 300 且触发止损，When 查看通知，Then 文案指向波段仓且底仓数量在提醒后仍为 500（在用户未改仓前提下）。
- Given 波段已清空仍有底仓，When 刷新列表，Then 不回到「空仓监控」主状态。
- Given 交易型触发止损，When 查看通知，Then 文案与 V2 一致、无波段前缀。

## 非功能要求

- 回归测试覆盖：同一行情 fixture 下 CORE_VALUE 与 TACTICAL 作用范围差异。

## 关联数据

- `positions.satellite_*`、`alert_logs.signal_type`
