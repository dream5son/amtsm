# 用户故事 11：价值策略相关异常与边界提示

## 场景目标

把 tier 降级、无 Hold 对比、代理规则、存量持仓不自动拆层等边界用清晰 UI 提示收口，避免静默误导。

## 用户故事

作为一名使用新策略框架的投资者，
我希望在危险或不确定操作时看到明确提示，
以便我不会误以为系统已自动按估值交易或已把旧持仓拆成底仓。

## UI 体现要点

- 降级失败：toast/弹窗说明须先处理底仓。
- 回测无建仓：详情 Hold 区显示「策略未建仓，无法对比」。
- 旧回测任务缺新字段：提示「请重新回测以生成相对持有对比」。
- `PRICE_PROXY` / 复核代理：配置页与通知中的「非真实估值/非基本面」披露。
- 首次升级为 `CORE_VALUE` 且已有持仓：提示「现有持仓不会自动拆成底仓，请按需调整」。

## 参与角色

- 用户
- 各相关弹层与表单校验
- API 错误码/消息

## 前置条件

- V3 相关功能已部分或全部上线。

## 触发事件

- 用户触发上述边界操作或打开缺数据的详情。

## 主流程

1. 前端展示校验/空态/披露文案。
2. 后端对非法状态返回可理解错误，不部分写入。

## 业务规则

- 所有自动代理规则必须可被用户识别为代理。
- 存量迁移不臆测底仓比例。
- 回测免责声明始终可见。

## 验收标准（Given-When-Then）

- Given 仍有底仓，When 降级为交易型，Then 失败且持仓不变。
- Given 回测无成交建仓，When 打开详情，Then 不显示伪造的 alpha=0 成功对比。
- Given 启用价格代理建仓，When 查看配置或通知，Then 可见非估值披露。
- Given 旧成功任务无 Hold 字段，When 打开详情，Then 引导重新回测而非空白报错。

## 非功能要求

- 错误文案可供测试用例稳定断言（建议错误码）。
