# 用户故事 11：收盘后日行情快照落库

## 场景目标
系统在收盘后将当日 OHLCV 及换手率写入快照表，供追溯与分析使用。

## 用户故事
作为一名希望复盘策略表现的投资者，
我希望系统每天自动保存关键行情快照，
以便后续做信号追踪和结果分析。

## 参与角色
- 定时任务（APScheduler）
- 日线数据源
- SQLite 数据库

## 前置条件
- 当日交易结束。
- 自选股中存在状态为 `NORMAL` 的股票。

## 触发事件
- 每个交易日 15:30 触发收盘任务。

## 主流程
1. 读取可监控股票列表。
2. 批量拉取当日 OHLCV 与换手率。
3. 对每只股票执行 UPSERT。
4. 记录成功与失败日志。

## 业务规则
- 写入主键为 `stock_code + trade_date`。
- 若个别股票缺失数据，仅跳过该股票，不阻塞全量任务。
- 非交易日任务可空跑并记录提示日志。

## 验收标准（Given-When-Then）
- Given 当日有交易数据，When 任务执行，Then 每只正常股票均写入或更新一条快照。
- Given 某股票缺失数据，When 执行落库，Then 该股票记录 warning 且其他股票继续写入。
- Given 重复执行同一交易日任务，When UPSERT，Then 不产生重复主键冲突。

## 非功能要求
- 任务运行结果需可观测，统计成功数、失败数、跳过数。
- 支持失败重试与告警。

## 关联数据
- 表：`daily_market_snapshots`
- 字段：`open_price`、`high_price`、`low_price`、`close_price`、`volume`、`turnover_rate`
