# 用户故事 02：登记买入（建仓 / 加仓）

## 场景目标
用户对自选股登记买入，系统维护加权成本与持仓数量，并将状态切换为持仓风控模式。

## 用户故事
作为一名需要手动登记真实成交的投资者，
我希望在自选列表操作区对任意自选股登记买入数量、价格与日期，
以便系统按加权成本跟踪持仓并启动止盈止损。

## UI 体现要点
- 每行操作区提供「登记买入」按钮。
- 点击后弹出表单：买入数量、买入价格、买入日期（默认今日，可改）。
- 加仓场景在确认前提示「加仓后新成本价 / 新止损参考价」（见故事 12）。
- 提交成功后列表就地刷新：状态变为「持仓中」，持仓字段更新。

## 参与角色
- 用户
- 前端操作区与买入弹层
- 后端持仓服务

## 前置条件
- 目标股票已在自选池。

## 触发事件
- 用户点击某行「登记买入」并提交表单。

## 主流程
1. 用户打开买入弹层并填写数量、价格、日期。
2. 系统校验字段合法。
3. 若已有持仓，按加权平均成本法更新成本与数量；不重置持仓期间最高价。
4. 状态切为「持仓中」，止盈止损引擎对该股生效。
5. 列表刷新展示新成本与止损参考价。

## 业务规则
- 加权成本：`AvgCost_new = (AvgCost_old×Qty_old + Price_buy×Qty_buy) / (Qty_old + Qty_buy)`。
- 加仓不重置 `HighestSinceHold`。
- 已持仓股票默认停止推送 V1 买入信号（除非开启加仓提醒，见故事 07）。

## 验收标准（Given-When-Then）
- Given 空仓股票，When 登记买入成功，Then 状态变为「持仓中」，显示数量与成本，并出现止损参考价。
- Given 已有持仓，When 再次登记买入，Then 数量累加、成本按加权更新，持仓期间最高价不归零。
- Given 数量或价格非法，When 提交，Then 弹层内提示错误且不写库。

## 非功能要求
- 提交后 1 秒内列表可见最新持仓字段。

## 关联数据
- 持仓表、买入流水表
