# 用户故事 08：自选操作区触发回测

## 场景目标

用户在自选列表操作区点击「回测」，对当前股票（或批量）发起历史回测任务，并在 UI 上看到进度与完成状态。

## 用户故事

作为一名需要在建仓前验证参数有效性的投资者，
我希望在关注列表操作区直接点击回测按钮启动回测，
以便用历史数据评估当前策略参数，而无需离开主界面。

## UI 体现要点

- **每只自选股行的操作区**提供「回测」按钮（与登记买入/减持、流水、移除等并列）。
- 点击后可弹出轻量确认/配置层：回测区间从该股票上市到现在、参数来源（当前全局/单股配置，或自定义一组）。
- 运行中：按钮变为 loading / 「回测中」，行内可显示进度态。
- 完成后：第一列圆环更新（故事 09）；可 toast「回测完成」。

## 参与角色

- 用户
- 前端操作区与回测配置弹层
- 回测引擎 / 任务 API

## 前置条件

- 股票在自选池；历史日线数据可获取（不足时见故事 12）。

## 触发事件

- 用户点击操作区「回测」并确认发起。

## 主流程

1. 用户点击「回测」。
2. （可选）选择区间与参数组合后确认。
3. 系统创建回测任务，按日回放：空仓用买点建仓，持仓用三级止损体系离场。
4. 任务完成后写入回测结果，前端刷新该行第一列圆环与可点开详情。



## 业务规则

- 回测与实盘信号复用同一套买卖/止盈止损判定逻辑；回测阶段不模拟「分批止盈」「持仓中加仓」开关，只跑最简化的三级止损体系满仓进出。
- 回测为离线模拟，不产生实盘通知或委托。
- 默认参数取该股当前生效的 (N, X, Y, StopLossPct, TrailingLadder)。
- 支持后续扩展：多组参数网格（在确认层增加「添加参数组合」）；同一次提交的多组参数共享同一个对比分组，供故事 10 详情页的多参数对比表整体取用。
- 若同一股票、同一参数、同一回测区间已有任务在执行中，重复点击「回测」直接复用该任务，不重复创建，避免历史记录堆积（对应按钮态见验收标准第二条）。



## 验收标准（Given-When-Then）

- Given 自选列表有股票，When 查看操作区，Then 每行可见「回测」按钮。
- Given 用户点击回测并确认，When 任务执行中，Then 该行呈现回测中状态且按钮不可重复乱点（或明确提示已在进行）。
- Given 回测成功完成，When 刷新列表，Then 第一列出现/更新盈利几率圆环（故事 09）。
- Given 回测失败（数据源错误），When 结束，Then UI 提示失败原因，圆环保持原值或失败占位。



## 非功能要求

- 回测不阻塞列表其他操作；长耗时任务需异步 + 可轮询/SSE 状态。
- 界面需提示回测不保证实盘可复现。



## 关联数据

- 回测任务表、历史日线缓存、当前策略配置
