# 用户故事 12：持仓与回测相关异常的 UI 提示

## 场景目标
将 PRD 中持仓/回测边界情况转化为界面可感知的校验、确认与提示，避免静默错误。

## 用户故事
作为一名依赖系统提示规避误操作的投资者，
我希望在加仓、减持、除权、T+1、回测样本不足等场景看到明确 UI 提示，
以便理解风险敞口变化并正确解读回测结果。

## UI 体现要点（按场景）
1. **加仓摊薄成本**：确认页展示「加仓后新成本价 / 新止损参考价」。
2. **减持超量**：表单内联错误，禁止提交。
3. **T+1**：止损/止盈通知与（若有）信号详情中，对当日买入部分标注无法当日卖出说明。
4. **涨跌停**：信号/通知附加涨跌停风险提示（列表信号旁可选 icon + tooltip）。
5. **回测样本不足**：详情与圆环 tooltip 提示「样本不足，仅供参考」。
6. **回测数据不足/失败**：操作区回测反馈错误原因；圆环失败占位。
7. **参数已变更未重跑**：圆环旁「过期」角标。

## 参与角色
- 用户
- 前端表单/列表/回测详情
- 后端校验与计算

## 前置条件
- 视具体场景触发。

## 触发事件
- 用户提交加仓/减持、查看信号、发起或查看回测等。

## 主流程
1. 系统在对应操作节点返回业务校验或提示元数据。
2. 前端以确认框、inline error、tooltip、角标等方式展示。
3. 用户据此确认、修改或仅知悉风险。

## 业务规则
- 除权除息对成本与持仓最高价的调整以后台为准；若当日发生调整，列表成本/止损价刷新即可（可选 toast「已按除权因子调整持仓成本」）。
- 不允许出现负持仓。
- 回测免责声明在回测相关弹层常驻。

## 验收标准（Given-When-Then）
- Given 加仓操作，When 进入确认，Then 可见新成本与新止损参考价。
- Given 减持数量大于持仓，When 提交，Then 被拒绝并提示。
- Given 回测交易次数过少，When 查看圆环/详情，Then 可见样本不足提示。
- Given 回测失败，When 任务结束，Then 操作区或 toast 展示失败原因。

## 非功能要求
- 错误文案可读、可行动（告诉用户下一步做什么）。

## 关联数据
- 持仓校验错误码、回测任务状态与错误信息
