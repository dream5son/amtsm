# 用户故事 03：登记减持（部分 / 全部卖出）

## 场景目标
用户对持仓股票登记部分或全部卖出，系统正确扣减数量、保留或清空成本相关状态，并切换列表状态。

## 用户故事
作为一名需要手动登记卖出成交的投资者，
我希望在操作区登记减持数量、价格与日期，
以便系统同步持仓数量，并在清仓后回到空仓监控。

## UI 体现要点
- 仅「持仓中 / 部分减持」行显示「登记减持」按钮（空仓隐藏或禁用）。
- 减持弹层：卖出数量、卖出价格、卖出日期；展示当前可卖数量。
- 全部卖出时二次确认「将清仓并清空止盈止损状态」。
- 成功后列表刷新：部分减持保留成本；清仓回「空仓监控」。

## 参与角色
- 用户
- 前端操作区与减持弹层
- 后端持仓服务

## 前置条件
- 目标股票持有数量 > 0。

## 触发事件
- 用户点击「登记减持」并提交。

## 主流程
1. 用户填写卖出数量、价格、日期。
2. 系统校验卖出数量 ≤ 当前持有数量。
3. 部分减持：扣减数量，成本不变，状态为「部分减持」。
4. 全部减持：数量归零，清空成本、持仓最高价、动态止损线，状态回「空仓监控」。
5. （加分）展示本笔已实现盈亏。

## 业务规则
- 减持不改变剩余仓位加权成本。
- 清仓后重新进入 V1 空仓买卖点监控。
- 已实现盈亏 = `(卖出价 - 成本价) × 卖出数量`（展示加分项）。

## 验收标准（Given-When-Then）
- Given 持仓 1000 股，When 卖出 400 股，Then 剩余 600，成本不变，状态为「部分减持」。
- Given 持仓 1000 股，When 卖出 1000 股，Then 状态为「空仓监控」，成本与止损参考价清空。
- Given 卖出数量 > 持有数量，When 提交，Then UI 拒绝并提示错误。

## 非功能要求
- 前后端双重校验，禁止负持仓。

## 关联数据
- 持仓表、减持流水表
