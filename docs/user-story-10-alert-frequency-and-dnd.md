# 用户故事 10：告警频控与勿扰控制

## 场景目标
防止阈值附近震荡导致重复通知，并确保非交易时间不发送消息。

## 用户故事
作为一名不希望被告警轰炸的投资者，
我希望同一只股票同一种信号每天只提醒一次，
并且非交易时间不接收任何通知。

## 参与角色
- 行情计算引擎
- 内存频控组件（Set）
- SQLite 唯一索引约束
- 通知组件（wechatpy）

## 前置条件
- 触发了 BUY 或 SELL 条件。

## 触发事件
- 引擎准备发送通知前执行频控检查。

## 主流程
1. 校验当前是否处于交易时段。
2. 检查内存去重键：`stock_code + trade_date + signal_type`。
3. 若内存未命中，尝试写入 `alert_logs`（依赖唯一索引兜底）。
4. 写入成功才发送微信。
5. 发送后更新内存去重状态。

## 业务规则
- 单日频控粒度：股票 + 日期 + 信号类型。
- 内存频控与数据库唯一索引双保险。
- 非交易时间直接丢弃信号，不触发发送。

## 验收标准（Given-When-Then）
- Given 同一股票同一日首次触发 BUY，When 执行频控，Then 允许发送。
- Given 同一股票同一日再次触发 BUY，When 执行频控，Then 阻断发送。
- Given 当前为非交易时间，When 出现阈值触发，Then 不发送任何通知。
- Given 并发触发同一信号，When 写库竞争，Then 仅一条成功，其他因唯一约束被拒绝。

## 非功能要求
- 频控逻辑应为 O(1) 查验，不拖慢主循环。
- 唯一索引冲突应被捕获并记为预期行为日志。

## 关联数据
- 表：`alert_logs`
- 索引：`idx_freq_limit(stock_code, trade_date, signal_type)`
