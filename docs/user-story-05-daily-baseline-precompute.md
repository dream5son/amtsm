# 用户故事 05：盘前基准值预计算（前复权）

## 场景目标
系统在交易日前（08:30）预计算每只股票的 N 日高低基准，盘中仅做 O(1) 阈值比较。
同时在前端首页关注列表中可实时感知任务执行状态，并可查看执行日志。

## 用户故事
作为一名依赖实时告警的投资者，
我希望系统在开盘前完成基准值准备，
并在首页实时看到后台任务是否正在执行与是否失败，
以便盘中能稳定、快速地判断买卖信号，并及时发现任务异常。

## 参与角色
- 定时任务（APScheduler）
- 数据源接口（Tushare/BaoStock 等）
- 行情计算引擎
- SQLite 数据库
- 前端首页关注列表（Watchlist）
- 后端任务状态与日志查询接口

## 前置条件
- `watchlist` 中存在状态为 `NORMAL` 的股票。
- 第三方日线接口可用并支持前复权数据。
- 前端已打开首页并展示关注列表。

## 触发事件
- 每个交易日 08:30 触发盘前任务。
- 用户打开首页后，前端主动拉取/订阅任务状态。

## 主流程
1. 读取全部正常股票及其生效参数 N。
2. 批量拉取前复权历史日线数据。
3. 对每只股票剔除当日后计算 `Low_min` 与 `High_max`。
4. 若历史数据不足 N 天，则以实际 K 天计算并记录 `actual_n`。
5. 写入 `daily_baselines` 并同步到内存 `BaselineCache`。
6. 任务开始时写入任务日志主记录，状态置为“执行中”。
7. 每只股票处理过程写入明细日志（成功/失败、错误原因、耗时）。
8. 任务结束后汇总结果：全部成功则回到“未开始”，有失败则置为“执行失败”。
9. 前端关注列表新增“任务状态”列，首页打开后实时刷新并展示状态。
10. 用户点击状态按钮可查看本次或最近一次任务执行日志。

## 前端 UI 体现
- 关注列表新增列：`定时任务状态`。
- 状态值限定为：`未开始`、`执行中`、`执行失败`。
- 状态展示建议：
	- 未开始：灰色标签
	- 执行中：蓝色标签 + 动画指示（如加载点）
	- 执行失败：红色标签
- 行内提供 `查看日志` 按钮（或状态可点击），点击后打开日志面板/弹窗。
- 日志视图至少包含：开始时间、结束时间、总股票数、成功数、失败数、失败原因摘要、逐股明细。
- 实时性要求：前端状态与后端实际状态的可见延迟不超过 5 秒。

## 业务规则
- 必须使用前复权数据。
- N 日范围不含当日。
- 新股数据不足时采用 K 天降级策略，K=0 时记录异常。
- 任务状态机：`未开始 -> 执行中 -> 未开始/执行失败`。
- “执行失败”定义：本次任务存在任意股票处理失败，或任务中途异常终止。
- 同一时间仅允许一个盘前基准任务实例处于“执行中”。
- 日志记录失败不得影响主任务流程，但需写入降级告警（例如控制台错误+计数）。

## 异常与恢复
- 若第三方接口整体不可用：本次任务状态置为“执行失败”，并记录全局错误日志。
- 若个股数据获取失败：仅该股票记录失败，其他股票继续处理。
- 若首页加载时后端不可达：前端显示最近一次已知状态，并提示“状态获取失败，请稍后重试”。

## 验收标准（Given-When-Then）
- Given 历史数据充足，When 任务执行，Then `daily_baselines` 生成当日基准记录。
- Given 股票仅有 K<N 天数据，When 计算，Then `actual_n` 应为 K 且计算成功。
- Given 某股票无可用历史数据，When 任务执行，Then 该股票标记异常并不中断其他股票处理。
- Given 前端已打开首页，When 后端任务开始执行，Then 关注列表在 5 秒内显示“执行中”。
- Given 本次任务任一股票失败，When 任务结束，Then 关注列表显示“执行失败”且可查看失败明细日志。
- Given 用户点击“查看日志”，When 日志拉取成功，Then 可看到任务汇总与逐股执行明细。
- Given 任务执行成功且无失败，When 任务结束，Then 状态回到“未开始”并可查看本次成功日志。

## 非功能要求
- 任务应支持失败重试与告警。
- 计算过程应尽量批量化，降低外部 API 调用次数。
- 状态查询接口应轻量，支持高频读取（首页轮询或实时订阅）。
- 日志写入应保证可追溯性（至少保留最近 30 天）。
- 日志查询接口默认分页，避免一次性返回过大明细。

## 关联数据
- 表：`watchlist`、`daily_baselines`
- 字段：`low_min`、`high_max`、`actual_n`、`trade_date`

## 新增数据表（执行日志）
- 表：`baseline_job_logs`
- 用途：记录每次盘前基准任务执行的汇总日志。
- 建议字段：
	- `id`：主键
	- `job_name`：任务名称（如 `daily-baseline-precompute`）
	- `trade_date`：交易日
	- `status`：`RUNNING` / `SUCCESS` / `FAILED`
	- `started_at`：开始时间
	- `finished_at`：结束时间，可空
	- `total_count`：总处理股票数
	- `success_count`：成功数
	- `failed_count`：失败数
	- `error_summary`：错误摘要，可空
	- `created_at` / `updated_at`：审计时间

- 表：`baseline_job_log_items`
- 用途：记录每只股票的执行明细日志。
- 建议字段：
	- `id`：主键
	- `job_log_id`：外键，关联 `baseline_job_logs.id`
	- `stock_code`：股票代码
	- `stock_name`：股票名称，可空
	- `strategy_n`：本次使用的 N
	- `actual_n`：实际参与计算天数
	- `status`：`SUCCESS` / `FAILED`
	- `low_min`：计算结果，可空
	- `high_max`：计算结果，可空
	- `error_message`：失败原因，可空
	- `processed_at`：处理时间

## 接口建议（用于前端状态与日志查看）
- `GET /api/jobs/daily-baseline/status`
	- 返回当前状态：`未开始`、`执行中`、`执行失败`，以及最近一次任务摘要。
- `GET /api/jobs/daily-baseline/logs/latest`
	- 返回最近一次任务汇总及明细（支持分页参数）。
- `GET /api/jobs/daily-baseline/logs/{job_log_id}`
	- 按任务 ID 查询指定日志详情。
