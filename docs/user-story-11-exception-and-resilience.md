# 用户故事 11：异常与容错处理

## 场景目标
系统在除权、新股数据不足、接口超时、停牌等异常场景下保持可用并避免误报。

## 用户故事
作为一名依赖系统稳定性的投资者，
我希望系统在数据异常或网络故障时仍能安全运行，
以便减少漏报、误报和服务中断。

## 参与角色
- 行情计算引擎
- 盘前基准任务
- 第三方行情接口
- 前端状态展示

## 前置条件
- 系统已接入日线与实时行情接口。

## 触发事件
- 出现除权除息、新股数据不足、网络超时、停牌等任一异常。

## 主流程
1. 盘前任务使用最新前复权重算基准，处理除权影响。
2. 对数据不足 N 天股票按 K 天降级计算。
3. 实时接口超时时执行指数退避重试最多 3 次。
4. 连续失败达到阈值后标记“行情延迟”并记录内部告警。
5. 停牌股票自动更新状态为 `HALT` 并暂停监控。

## 业务规则
- 除权场景下必须使用前复权数据。
- 连续 5 次拉取失败应触发系统级异常标识。
- 停牌和退市股票应从实时计算链路剔除。

## 验收标准（Given-When-Then）
- Given 股票发生除权除息，When 次日盘前计算，Then 基准值应与前复权口径一致且不产生虚假买点。
- Given 股票上市不足 N 天，When 计算基准，Then 使用 K 天并在前端显示数据不足提示。
- Given 实时行情接口超时，When 触发重试策略，Then 在重试上限内自动恢复或进入延迟状态。
- Given 股票停牌，When 轮询解析，Then 状态更新为 `HALT` 且后续不再计算。

## 非功能要求
- 异常链路应有结构化日志，便于追溯。
- 故障隔离: 单只股票异常不应拖垮全量任务。
