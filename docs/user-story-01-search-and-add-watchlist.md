# 用户故事 01：搜索并添加自选股

## 场景目标
用户在主界面的辅助搜索区通过股票代码、拼音首字母或中文名称搜索 A 股标的，并将其加入自选股池。

## 用户故事
作为一名需要快速建立监控列表的投资者，
我希望通过多种关键词搜索股票并一键添加到自选股，
以便系统开始对该股票进行策略监控。

## 参与角色
- 用户
- 前端主界面（Next.js 监控工作台）
- 后端 API（FastAPI）
- 股票基础信息数据源

## 前置条件
- 用户已登录系统（如 V1 未做登录，可视为默认单用户）。
- 股票基础信息服务可用。

## 触发事件
- 用户在主界面“辅助搜索”输入 `600519`、`GZMT` 或 `贵州茅台`，点击“搜索”，并在结果中点击“加入自选”。

## 主流程
1. 用户在主界面输入关键词并发起搜索。
2. 系统返回匹配股票列表（代码、名称、交易所）。
3. 用户在结果区点击“加入自选”。
4. 系统校验该股票未重复存在于自选池。
5. 系统写入 `watchlist` 并返回成功。
6. 主界面内联刷新自选列表，展示新增股票，无需页面跳转。

## 业务规则
- 支持沪深北交所 A 股范围。
- 股票代码在存储时统一标准化（如 `sh600519`、`sz000001`）。
- 重复添加同一股票时，返回幂等提示，不重复写库。

## 验收标准（Given-When-Then）
- Given 用户在主界面输入有效代码，When 点击“加入自选”，Then 股票应出现在主界面自选列表且状态为 `NORMAL`。
- Given 用户输入拼音首字母，When 存在匹配标的，Then 系统返回可选列表。
- Given 股票已在自选池，When 再次添加，Then 系统返回“已存在”且不新增记录，同时结果区按钮展示“已加入”不可点击。
- Given 输入无匹配关键词，When 搜索，Then 主界面搜索区展示“未找到相关股票”。

## 非功能要求
- 搜索接口 P95 响应时间不高于 1 秒。
- 添加接口在并发下保持幂等与数据一致性。

## 关联数据
- 表：`watchlist`
- 字段：`stock_code`、`stock_name`、`status`、`created_at`

## SDK 调研结论（2026-08-04）

### 候选方案对比
- AkShare
	- 优点：开源免费、无需 token、A 股股票列表接口可直接用于代码和名称检索，接入成本低。
	- 风险：上游数据接口偶发变更，需要做本地缓存和降级处理。
- Tushare
	- 优点：数据维度完整、生态成熟。
	- 风险：通常需要注册与 token，部分能力依赖积分或权限，不适合作为 V1 零门槛搜索入口。
- BaoStock
	- 优点：接口稳定、历史数据能力较好。
	- 风险：登录会话与字段体系相对独立，做前端搜索补全时开发成本更高。

### 选型
- V1 选用 `AkShare + pypinyin`。
- 理由：
	- 满足“代码 + 中文名 + 拼音首字母”三种搜索模式。
	- 后端 Python 技术栈可直接集成，避免额外鉴权流程。

## 搜索实现逻辑（已落地）

### 后端接口
- `GET /api/stocks/search?q=<keyword>&limit=<n>`
- 返回字段：`stock_code`（标准化，如 `sh600519`）、`stock_name`、`exchange`（`SH/SZ/BJ`）

### 关键规则
- 代码标准化：
	- 输入 `600519` -> `sh600519`
	- 输入 `000001` -> `sz000001`
	- 输入 `430047`/`8xxxxx` -> `bjxxxxxx`
	- 输入已标准化代码（`sh/sz/bj` + 6 位）直接透传。
- 匹配维度：
	- 股票代码精确/前缀匹配
	- 中文名称精确/包含匹配
	- 拼音首字母匹配（如 `GZMT` 命中 `贵州茅台`）
- 排序策略：
	- 精确代码 > 代码前缀 > 首字母精确 > 首字母前缀 > 名称匹配 > 其他弱匹配
- 性能策略：
	- 股票基础信息做 12 小时内存缓存，避免每次搜索都请求上游。

### 前端交互
- 主界面内置“辅助搜索”区域，支持输入关键词发起搜索。
- 结果列表展示：代码、名称、交易所。
- 支持“加入自选”按钮调用 `POST /api/watchlist`。
- 重复添加时展示“已存在”，不重复写库。
- 添加完成后主界面自选列表即时刷新。
