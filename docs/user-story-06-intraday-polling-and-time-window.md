# 用户故事 06：交易时段内实时轮询与信号判定

## 场景目标
系统仅在 A 股交易时段执行实时行情轮询并判定策略信号。

## 用户故事
作为一名不想被无效信息打扰的投资者，
我希望系统只在交易时间运行实时监控，
以便我收到的告警都来自可交易时段。

## 参与角色
- 行情计算引擎
- 实时行情 API（腾讯/新浪）
- SQLite 数据库

## 前置条件
- 当日 `BaselineCache` 已初始化。
- 自选池中存在可监控股票。

## 触发事件
- 引擎常驻进程启动并进入轮询循环。

## 主流程
1. 检查当前是否处于交易时段（09:30-11:30, 13:00-15:00）。
2. 若不在交易时段，进入 sleep，不做计算。
3. 若在交易时段，按批次拼接股票代码拉取实时行情。
4. 解析实时价格并执行买卖阈值判断。
5. 对停牌股票更新状态并跳过。

## 业务规则
- 批量请求建议每批不超过 50 只。
- 轮询间隔建议 3 到 5 秒。
- 非交易时间不发送任何通知。

## 验收标准（Given-When-Then）
- Given 当前时间为 10:00，When 引擎轮询，Then 应执行实时行情请求与信号计算。
- Given 当前时间为 16:00，When 引擎轮询，Then 不应请求行情且不应发送通知。
- Given 某股票返回停牌标识，When 解析数据，Then 将其标记为 `HALT` 并跳过当次计算。

## 非功能要求
- 支持批量拉取与超时重试，保证监控连续性。
- 轮询逻辑需可观测，提供运行日志与错误计数。

## 关联数据
- 表：`watchlist`
- 内存：`BaselineCache`
