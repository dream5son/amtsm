# 用户故事 06：交易时段内实时轮询与信号判定

## 场景目标
复用用户故事 05 已生成的当日基准值，仅在 A 股交易时段批量拉取实时行情并完成阈值判定，为后续告警流程输出 BUY/SELL 候选信号。

## 用户故事
作为一名依赖盘中信号的投资者，
我希望系统只在交易时段使用盘前已准备好的基准值监控价格，
以便及时获得有效信号，同时避免非交易时段产生无效请求和信号。

## 与用户故事 05 的边界
- 05 负责计算并持久化 `low_min`、`high_max`、`actual_n`，同时写入 `runtime_state.baseline_cache`。
- 06 只消费 05 的计算结果，不拉取历史日线、不重复计算 N 日高低点，也不写入 `daily_baselines`。
- 进程在 08:30 任务完成后重启时，06 可从当日 `daily_baselines` 恢复缓存；恢复只读取已有结果，不触发重新计算。
- 当日某只股票没有可用基准时，06 跳过该股票并记录原因，不使用前一交易日基准兜底。
- 06 只产出 BUY/SELL 候选信号；微信发送由 07、08 负责，单日频控与勿扰控制由 09 负责。

## 当前实现基础
- `baseline_precompute_task()` 已将当日基准写入 `runtime_state.baseline_cache`。
- `daily_baselines` 已提供按日期读取基准的仓储方法。
- `market_polling_task()` 当前仍为占位实现，尚未加入调度器。
- `market_data_service` 当前只有前复权日线接口，尚未实现批量实时行情接口。

## 参与角色
- APScheduler
- 行情计算引擎
- 实时行情 API（腾讯/新浪）
- 内存 `runtime_state.baseline_cache`
- SQLite（只读关注列表、策略参数及当日基准）

## 前置条件
- 用户故事 05 已成功生成至少一只股票的当日基准，或数据库中存在可恢复的当日基准。
- `watchlist` 中存在状态为 `NORMAL` 的股票。
- 全局策略参数及单股覆盖参数可读取。

## 触发事件
- APScheduler 每隔配置的轮询间隔触发一次 `market_polling_task()`。
- 每次任务先执行交易日和交易时段校验。

## 主流程
1. 使用 `Asia/Shanghai` 时区获取当前日期和时间。
2. 判断当前是否为交易日，并处于 `09:30-11:30` 或 `13:00-15:00`；否则立即返回，不请求实时行情。
3. 获取 `NORMAL` 股票及其有效买卖系数：`X = custom_x or global_buy_x`，`Y = custom_y or global_sell_y`。
4. 从 `runtime_state.baseline_cache` 读取当日基准；若缓存为空，则从 `daily_baselines` 恢复当日数据一次。
5. 过滤掉没有当日基准的股票，按每批最多 50 只拼接代码并拉取实时行情。
6. 解析最新价、成交状态及必要的行情时间；无有效最新价或明确停牌的股票仅跳过当轮判定。
7. 对每只有效行情执行 O(1) 比较：
	- BUY 候选：`P <= low_min * X`
	- SELL 候选：`P >= high_max * Y`
8. 将候选信号交给 07/08 的告警流程；未触发时不产生后续动作。
9. 记录本轮请求批次数、成功/失败股票数、跳过原因、接口耗时和候选信号数。

## 业务规则
- 交易时段使用左闭右闭边界：`09:30:00-11:30:00`、`13:00:00-15:00:00`。
- 周末及非交易日不轮询；节假日判断应封装为可替换的交易日历能力。
- 轮询间隔默认 5 秒，并通过配置项管理。
- 单批最多 50 只；多个批次失败时相互隔离。
- 同一轮询任务只允许一个实例执行；上一轮未完成时不并发启动下一轮。
- 只接受属于当前交易日且字段合法的行情，零价、空价或过期行情不得参与判定。
- 盘中停牌属于实时状态，不直接将 `watchlist.status` 持久化为 `HALT`。当前 05 只处理 `NORMAL` 股票，永久写入 `HALT` 会导致次日基准任务无法自动恢复该股票；持久化停牌及复牌探测应另行设计。
- 缺少当日基准时必须跳过，不允许在盘中调用 05 的计算流程。
- 非交易时间不得请求实时行情，也不得产生候选信号。

## 异常与恢复
- 实时行情接口超时：按批次有限重试；重试仍失败则记录错误并等待下一轮，不阻塞其他批次。
- 部分股票响应缺失或解析失败：仅跳过对应股票，其余股票继续判定。
- 缓存为空：从 `daily_baselines` 恢复当日基准；数据库也无数据时结束本轮并记录 warning。
- 单只股票缺少基准：跳过该股票并记录结构化原因，不终止整轮任务。
- 系统时间或行情时间不一致：拒绝过期行情并记录时间差，避免使用上一交易日价格误触发。

## 实现任务
1. 在配置中增加实时轮询间隔、批次大小和请求超时参数。
2. 实现可独立测试的交易日/交易时段判断函数。
3. 在 `market_data_service` 中增加批量实时行情获取与响应解析。
4. 实现当日基准缓存校验及数据库恢复，不复制 05 的计算逻辑。
5. 实现 `market_polling_task()` 的批处理、阈值比较和候选信号输出。
6. 将轮询任务加入 APScheduler，并配置 `max_instances=1` 与合并积压执行。
7. 增加交易时段、缓存恢复、缺失基准、停牌、批次失败和阈值边界测试。

## 验收标准（Given-When-Then）
- Given 当前为交易日上午 10:00 且存在当日基准，When 轮询任务触发，Then 批量请求实时行情并完成阈值比较。
- Given 当前为 11:31、12:30 或 15:01，When 轮询任务触发，Then 不请求行情且不产生候选信号。
- Given 当前为周末或非交易日，When 轮询任务触发，Then 立即返回。
- Given 内存缓存为空但数据库存在当日基准，When 首次盘中轮询，Then 恢复缓存后继续判定，且不重新拉取历史日线。
- Given 某只 `NORMAL` 股票没有当日基准，When 执行轮询，Then 跳过该股票且不使用历史日期基准。
- Given 某股票返回停牌或无有效最新价，When 解析行情，Then 仅跳过当轮判定，不将其永久排除出 05 的次日任务。
- Given 实时价恰好等于 `low_min * X` 或 `high_max * Y`，When 执行判定，Then 分别产生 BUY 或 SELL 候选信号。
- Given 一批行情请求失败，When 重试耗尽，Then 记录该批错误并继续处理其他批次。
- Given 上一轮任务尚未结束，When 下一调度时刻到达，Then 不并发执行第二个轮询实例。

## 非功能要求
- 单只股票的盘中判定复杂度为 O(1)，不得在轮询中执行历史日线计算。
- 外部请求必须设置超时和有限重试，避免调度线程长期占用。
- 日志不得在每个成功 Tick 上输出冗余明细；以轮次汇总、异常和候选信号为主。
- 时间判断、行情解析、批次处理和阈值判定应可通过注入时钟及模拟响应独立测试。

## 关联数据
- 只读表：`watchlist`、`strategy_config`、`daily_baselines`
- 内存：`runtime_state.baseline_cache`
- 复用字段：`low_min`、`high_max`、`actual_n`、`trade_date`
- 本故事不新增数据表
