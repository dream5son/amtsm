# 用户故事 03：自选列表展示与停牌状态同步

## 场景目标
系统在主界面核心自选区展示最新行情与状态，并正确标记停牌或退市股票。

## 用户故事
作为一名盯盘时间有限的投资者，
我希望在一个列表中看到自选股的最新价、涨跌幅和状态，
以便快速判断哪些股票正在正常监控，哪些已停牌。

## 参与角色
- 用户
- 前端主界面（Next.js 监控工作台）
- 后端 API（FastAPI）
- 行情引擎

## 前置条件
- 自选池中至少存在 1 只股票。

## 触发事件
- 用户进入主界面或手动刷新自选列表。

## 主流程
1. 前端请求自选列表数据。
2. 后端返回股票代码、名称、最新价、今日涨跌幅、状态。
3. 主界面渲染自选列表。
4. 若状态为 `HALT`，前端展示“停牌”标识。
5. 若存在数据不足天数，前端在备注列展示“数据不足 N 天”。

## 业务规则
- 停牌股票状态为 `HALT`，不参与策略计算。
- 退市股票状态为 `DELISTED`，默认不参与轮询。
- 数据不足 N 天的次新股可展示“数据不足 N 天”提示。

## 验收标准（Given-When-Then）
- Given 股票正常交易，When 拉取列表，Then 主界面自选区显示实时价格与涨跌幅。
- Given 股票盘中停牌，When 引擎识别停牌，Then 列表在下一次刷新显示 `HALT`。
- Given 股票状态为 `HALT`，When 监控引擎运行，Then 应跳过该股票计算。
- Given 股票上市不足 N 天，When 拉取列表，Then 备注列应展示“数据不足 N 天”。

## 非功能要求
- 列表接口支持分页或分批返回，避免大列表卡顿。
- 前端刷新频率与后端限流策略协调，避免无效请求。

## 关联数据
- 表：`watchlist`
- 字段：`status`、`stock_code`、`stock_name`
